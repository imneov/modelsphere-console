# 部署模型

模型部署由集群里的 swiss（swissd）执行：每次部署、升级、回滚都会先生成**部署计划**、预览变更，确认后才真正执行。

## 首次使用：初始化站点

如果 swissd 还没有站点配置，进入模型服务时会看到 **初始化站点** 页。填写这个集群的基本情况后保存：

- 模型目录：可部署的模型从哪里来
- chart 仓库与镜像仓库
- 模型路径模板：权重在节点上的存放位置

之后可以随时在 [站点配置](/inferences/site-profile) 修改，支持表单和 YAML 两种编辑方式，保存前服务端会先校验。

## 1. 在模型库里选模型

打开 [模型库](/inferences/catalog)：

- 用搜索框和筛选条件（系列、引擎、硬件、标签）缩小范围；勾选「仅调优过」只看有调优变体的模型。
- 点模型卡片进入详情。**变体**页列出这个模型的各种部署形态（GPU 型号、卡数、引擎），每个变体会显示「N 个节点可用」——这是按当前集群空闲 GPU 计算的适配结果。
- 在合适的变体上点 **部署**。

## 2. 填写部署表单

| 分区 | 主要字段 | 说明 |
|---|---|---|
| 基本信息 | 服务名、命名空间 | 服务名同时用作 helm release、路由、伸缩器和 SLO 的名字；只能用小写字母、数字和 `-`，最多 53 个字符。**部署后不能修改** |
| 资源与调度 | 自动伸缩 / 副本数、GPU 型号、容忍 | 自动伸缩默认开启，由 LLMScaler 在上下限之间管理副本数 |
| 路由 | 发布路由、路由路径、SLO、TTFT / TPS 阈值、ServiceMonitor | 控制请求如何进入推理实例，以及路由的服务目标和 Prometheus 采集配置 |
| 高级 | 覆盖 YAML | 一般不需要修改 |

多数字段留空即可，沿用站点配置和 chart 的默认值。

**自适应并发** 的总开关、下限比例、绝对下限、起始并发、空闲保持和 TTFT 判断位于同一区域，内部参数可从 **高级自适应参数** 添加。关闭后隐藏本组输入并清空已填写参数，再开启时不会恢复这些旧值。**默认节点并发上限** 留在 **容量与故障切换** 中，关闭自适应并发时也有效；它也影响自适应上下限使用的静态最大值。升级时仍需先检查差异再确认。

## 生成中断恢复

在部署或升级表单的 **路由 → 生成中断恢复** 中开启，填写权重对应的 **实际模型**，例如 `kimi-k3` 或 `glm-5.3`。它用于选择续写策略，不是客户端调用时使用的服务模型名。

- 需要启用 **CART**、**发布路由**，并选择 `sglang` chart **0.8.11+** 或 `vllm` chart **0.8.9+**；生成计划时会检查这些条件。
- **流式输出空闲超时** 控制开始输出后多久没有新片段视为卡顿；留空沿用已有超时或 chart 默认值。
- **执行中断续写** 默认开启；关闭时网关仅检测并记录中断，不发送续写请求。
- **缓冲工具调用** 会将参数保留到调用完整生成后一次性发送，以便在中断时重新生成。
- 请求路径为 `openresty → 恢复网关 → CART → 推理实例`，恢复网关随模型 release 部署；最终仍需预览变更并确认。
- 结构化 JSON 等不支持的请求直接透传。实际模型与引擎的兼容范围见 [恢复网关说明](https://github.com/modelsphere/continuation_gateway)，启用前应验证实际组合。量化版或微调版使用文档中的基础型号名；vLLM 搭配 Kimi-K3 需要 `--enable-scale-out`。
- 高级 YAML 在生成计划后参与校验，是否开启恢复及参数是否合法以最终值为准。
- 升级会带出已配置的恢复参数；关闭后再生成、确认计划可移除网关。高级 YAML 的优先级高于表单，检查最终计划和差异。

## L3 KV 缓存

在部署或升级表单的 **资源与调度 → L3 KV 缓存** 中，将注意力 KV 经主机内存卸载到已有存储后端。

| 引擎 / chart | L3 支持情况 |
|---|---|
| `sglang` **0.9.27+** | 使用 `storageKVOffload`，`backend: hicache`；首次发布于 [sglang-0.9.27](https://github.com/modelsphere/helm-charts/blob/sglang-0.9.27/charts/sglang/values.yaml) |
| `sglang` **0.9.26 及更早** | 没有顶层 `storageKVOffload`，需要先选择支持的 chart 版本 |
| `vllm` | 尚未实现。**0.8.23** 新增的保留配置会显式拒绝开启；已有本地 `mooncakeStore` 卸载属于 L2 |

1. 开启 L3 并选择存储后端。chart schema 接受 `mooncake`、`file`、`sim`、`npu_memcache`、`hf3fs`、`nixl`、`aibrix`、`dynamic`、`eic`、`simm`、`mori`、`shm`、`tensorcast` 和 `seaweedfs`。`sim` 仅用于模拟；schema 接受不代表实际引擎镜像包含该后端，仍需核实依赖及 HiCache 参数兼容性。
2. 可选的内存池大小、比例、模式和占比留空时使用引擎默认值；显式大小优先于比例。「更多 HiCache 参数」包含写入策略、I/O 后端、内存布局和预取配置。清空已设置的可选字段会移除该覆盖值；未修改的字段及表单外的配置会保留。
3. 后端配置可填写 JSON 对象或引擎容器内已挂载的 `@file` 路径。存储服务、配置挂载、凭据及网络访问需预先准备。`file` 后端需按实际引擎版本配置路径并提供可写存储卷；此表单不创建存储卷。
4. Mooncake 连接已有 Store，按实际部署填写 master、传输元数据服务、协议和传输设备；多轨网络应显式选择 HCA。全局段大小原样下发，纯客户端可设为 `0`。使用 `P2PHANDSHAKE` 时，在覆盖 YAML 的现有 `env` 配置中通过 `status.podIP` 设置 `MOONCAKE_LOCAL_HOSTNAME`。需要大页时，仍在 YAML 的 `storageKVOffload.mooncake` 下配置，提供 chart 要求的页大小、资源限额及集群容量。
5. 生成计划，检查最终计划和差异后确认。覆盖 YAML 优先，可开启或关闭 L3；chart 版本、引擎、后端、数值及冲突均在自适应并发清理完成后的最终计划上校验。

- SGLang `storageKVOffload` 包含 `localKVOffload` 的作用。如已开启本地卸载，需要在覆盖 YAML 中显式设置 `localKVOffload.enabled: false`，并将需要的 HiCache 参数移到 `storageKVOffload.hicache`，或者保持 L3 关闭。Console 会显示冲突，不会悄悄关闭已有本地卸载。
- 分离式 PD 中 L3 **只作用于 prefill**；合置 PD 不受支持。`commandOverride` 会替换引擎命令，不能与图形化 L3 配置同时使用。
- 目录或覆盖 YAML 的 `extraArgs`，以及 PD 的 `pd.prefill.extraArgs`，最后追加到引擎命令。若其中的 `--hicache-*` 与图形化 L3 值不同，会阻止进入预览。请在覆盖 YAML 中保留其他参数并移除重复项，或统一取值。例如 Kimi 配方已有 `--hicache-size=150` 时，图形化输入 `32` 不会直接生效；仅开启 L3 且保留该容量时可将图形化大小留空。
- 「高级」中的 **编译缓存** 使用 `cache` 保留节点上的编译内核，与 KV 卸载是独立功能；开启 L3 会保留它。
- 升级时从当前计划的最终合并 L3 值初始化，轮询计划不会重置正在编辑的参数。已有覆盖 YAML 仍优先于图形化输入，必要时应修改该 YAML。
- 此功能仅配置模型 release，不提供独立缓存服务管理器。生成计划或渲染成功不能验证真实后端及 GPU 执行。使用兼容引擎部署后，仍需通过实际 GPU 推理、引擎日志和指标验证连接及重复前缀的卸载与复用；开启开关不代表 GPU 或缓存命中已验证。

## 3. 预览并确认

点 **生成计划** 后进入预览：

- **部署计划**：这次部署由哪些配置层组合而成。
- **变更差异**：与集群现状相比将要改变的内容。
- **变更说明**：写下这次变更的原因，会记入操作记录。

确认无误后点 **确认部署**。

## 4. 等待就绪

在 [推理服务](/inferences) 列表查看状态：

| 状态 | 含义 |
|---|---|
| 部署中 | helm 正在执行 |
| 加载中 | Pod 已调度，正在读取模型权重 |
| 运行中 | 可以提供服务 |
| 失败 | 部署失败，到操作记录里看输出 |
| 未就绪 | 超过 1 小时仍未就绪，超出正常加载时间，需要排查 |

> **冷启动需要 20–40 分钟。** 大模型首次加载权重很慢，「加载中」通常不是出错。

点服务名进入详情，**概览**页按步骤展示进度：已应用 → 实例就绪 → 已接入路由 → 弹性伸缩。其他标签页：

| 标签 | 内容 |
|---|---|
| 实例 | Pod 列表、所在节点、重启次数 |
| 日志 | 按 Pod、容器查看最近日志 |
| 事件 | Kubernetes 事件，可只看告警（默认只保留 1 小时） |
| 版本管理 | 历史版本，可查看当时的 values 并回滚 |
| 操作记录 | 这个服务的部署、升级、回滚记录 |
| 部署计划 | 当前计划的组成 |

## 升级、回滚与卸载

在推理服务列表的行操作或详情页顶部操作：

- **升级**：修改模型版本、变体或设置，同样先预览差异再确认。服务名和命名空间不能改。
- **回滚**：在「版本管理」里选一个历史版本，原样恢复当时的计划。要改设置请用升级。
- **编辑 SLO**：调整扩缩容依据的延迟、吞吐目标和副本数上下限。部署时没开 SLO 的服务需要先在升级时打开。
- **卸载**：停止服务并删除 Pod，操作记录保留。重新安装需要重新加载权重。
- Pod 还在退出时，服务会以 **卸载中** 留在列表里；在它消失之前，升级、回滚、编辑 SLO 和卸载都不可用。
- 从详情页卸载后会留在当前页。**概览 → 卸载进度** 和 **实例** 页显示剩余 Pod 数；可点 **查看实例** 排查仍在退出的 Pod。支持上报删除进度的 LLMService 后端还会显示其清理说明。
- 卸载期间列表和详情每 3 秒刷新。Pod 清空后等待后端确认清理；读取状态失败时显示警告，不把空列表当成卸载完成。这个刷新间隔不改变 Pod 的退出宽限期或实际清理速度。

列表上的「落后目录」表示目录里有更新的版本，可以升级；「未纳管」表示这个 release 不是通过 swiss 部署的，不能在这里升级。

## 编辑目录中的变体

catalog-server 目录可以在模型详情页直接编辑。在 [站点配置](/inferences/site-profile) 的编辑器中把该目录勾选为 **可写**，并填入 catalog-server 的 **写入令牌**；令牌由 swissd 保存在它自己的 Secret 中。之后修改该目录除 **默认** 之外的任何设置（URL、名称、取消勾选 **可写**）都会移除令牌：修改时请重新输入。保存时会先向 catalog-server 校验令牌（新添加的目录也一样）：令牌不被接受或无法连接时，不会保存任何内容，编辑器会说明原因。每次修改都是目录的一次提交。

| 操作 | 入口 | 注意 |
|---|---|---|
| 初始化空目录 | 模型库工具栏的 **初始化目录** | 填写目录的发布地址和仓库；初始化之前无法添加模型 |
| 目录设置 | 模型库工具栏的 **目录设置** | 它的 `catalog.yaml`：`site`、`raw`、`repo` |
| 新增模型 | 模型库工具栏的 **新增模型** | 填写模型名和第一个变体 id、`metadata.yaml`，以及以目录中已有变体为副本的第一个变体 |
| 编辑模型 | 模型详情页头的 **编辑模型** | 它的 `metadata.yaml`：描述、默认变体、调优结果 |
| 新增变体 | 页头的 **新增变体** | 以默认变体为副本、版本 1.0.0 起步；修改其中的 `id`，它同时是文件名 |
| 编辑 | 变体卡片的 `⋯` 菜单 | 每次修改都要提升 `version`（可点 **升级版本号**）；**校验** 只检查不提交 |
| 删除 | 变体卡片的 `⋯` 菜单 | 默认变体、被调优结果引用的变体、模型的最后一个变体不能删除；历史记录会保留 |

- 可写目录在模型库的目录选择器中带有 **可编辑** 标记。
- 如果打开后文件已被他人修改，保存时会提示；重新加载后再编辑。
- 提交的作者是令牌的所有者，而不是当前用户。
- 如果令牌之后在 catalog-server 上被修改或移除，下一次修改时会提示；在站点配置编辑器中填入新令牌即可。
- 编辑需要模型部署后端（`swiss`）的权限：`update` 用于新增或修改变体、设置令牌，`delete` 用于删除变体或令牌。

## 节点与操作记录

- [节点](/inferences/nodes)：集群的 GPU 库存——空闲 GPU、单节点最大空位、各型号分布，以及不可用的节点。部署前可以在这里确认资源是否足够。
- [操作记录](/inferences/runs)：swissd 执行过的每一次部署、升级、回滚、卸载，展开一行可以看完整输出。

## 只读模式

如果操作按钮是灰色的，并提示「这个 swissd 是只读的」，说明集群上的 swissd 没有开启部署权限，只能查看。需要由运维在 swiss 的配置里打开 `allowDeploy`。
