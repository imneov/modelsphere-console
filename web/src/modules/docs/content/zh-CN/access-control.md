# 访问控制

访问控制管理谁能登录、能看到哪些页面、能做哪些操作。以下页面需要相应权限，通常由管理员使用。

## 用户

[用户](/iam/users) 页面：

- **新建用户**：填写用户名、显示名、邮箱和初始密码。新用户首次登录时会被要求设置自己的密码。
- 用户状态：活跃、禁用、待激活。
- 删除用户后，该用户无法再登录；不能删除当前登录的账号。

## 角色

[角色](/iam/roles) 页面：

- **新建角色**：在表格里勾选这个角色对「用户 / 角色 / 角色绑定」允许的操作（查看、列表、创建、更新、删除）。
- **成员**：在角色的行操作里打开，勾选拥有这个角色的用户。
- 删除角色后，持有它的用户会失去相应权限。

菜单能否看到由角色上的页面权限（`uiPermissions`）决定：

| 页面权限 | 对应菜单 |
|---|---|
| `swiss.view` | 模型服务 |
| `playground.use` | Playground |
| `apikeys.view` | 路由 → API 密钥 |
| `users.view` | 访问控制 → 用户 |
| `roles.view` | 访问控制 → 角色 |
| `loginrecords.view` | 访问控制 → 登录历史 |

页面权限和后端访问权限配置在集群里的 IAMRole 资源上，由集群管理员维护。管理员账号拥有全部权限。「使用文档」对所有登录用户可见。

## 登录历史

[登录历史](/iam/login-history) 记录每次登录的时间、用户、结果（成功 / 失败）、来源 IP 和 UserAgent，可按用户搜索，用于审计和排查异常登录。
